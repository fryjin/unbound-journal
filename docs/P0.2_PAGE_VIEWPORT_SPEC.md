# P0.2 — Page & Viewport Spec

## Goal

Create the renderer and gesture foundation that every future paper/content tool will share.

P0.2 does **not** paint paper. It establishes the page coordinate system and camera behavior first.

## Frozen page space

```text
Logical page: 1000 × 1400
Aspect ratio: 5:7
```

All future paper masks, ink points, media bounds, text bounds, selections and crop coordinates are stored in logical page coordinates.

Device CSS pixels are viewport coordinates only.

## Transform

The viewport transform is:

```text
screen.x = offsetX + page.x × scale
screen.y = offsetY + page.y × scale
```

Inverse:

```text
page.x = (screen.x - offsetX) / scale
page.y = (screen.y - offsetY) / scale
```

The math lives in `@unbound-journal/editor-core`, not in the Konva-only package.

## Fit behavior

Fit scale is the smaller of available width/page width and available height/page height after viewport padding.

At Fit:

- the full page is visible
- the page is centered on both axes
- zoom ratio is `1`

## Zoom

Range:

```text
Fit = 1×
Maximum = 4× Fit
```

Two-finger pinch zooms around the gesture center. The logical page point under the previous gesture center remains anchored under the moving gesture center, allowing zoom and pan in one gesture.

Desktop wheel zoom is provided for P0 QA and uses the pointer position as the focal point.

## Pan

P0.2 uses two-finger movement only.

Single-finger input is intentionally left unconsumed by viewport navigation so P0.3+ can assign it to Paper Brush / Paper Eraser / future object tools.

## Bounds

When a scaled page axis is smaller than the viewport, that axis is centered.

When it is larger, panning is clamped so the page cannot be thrown completely outside the viewport. A small edge margin remains available for comfortable inspection near page edges.

## Resize

`ResizeObserver` drives viewport dimensions.

On resize/orientation change:

- the current zoom ratio relative to Fit is preserved
- the logical page point near the old viewport center is preserved near the new viewport center
- bounds are re-applied

## DPR / Retina

The Stage is sized in CSS pixels. Konva manages its internal backing canvas at device pixel ratio, avoiding CSS upscaling of a low-resolution canvas.

The host exposes `data-device-pixel-ratio` for QA inspection.

No bitmap paper is rendered in P0.2; Paper Runtime image-resolution policy begins at the Paper Renderer stage.

## Public renderer handle

`PageViewportHandle` exposes:

- `fitToPage()`
- `screenToPage(point)`
- `pageToScreen(point)`
- `getState()`

P0.3+ tools should consume these APIs instead of duplicating coordinate math.

## P0.2 out of scope

- paper rendering
- paper brush
- eraser
- paper selection panel
- history
- persistence
- selection/transformer
- image/text/video/ink
