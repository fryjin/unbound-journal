# P1.1 — Release Notes

## Added

- `@unbound-journal/document-model` workspace package
- versioned `PageDocumentV2` with `paperLayers + elements`
- strict PageDocument decoder
- deterministic P0 `PaperPageDocumentV1` → P1 V2 migration
- unified `CommandHistory<PageDocument>` in the editor
- adapter that lifts accepted Paper Commands into PageDocument history
- generic Add / Remove / Transform / Reorder content commands
- renderer-independent content transform and hit-test geometry
- query-gated development placeholder ContentElement
- Konva `ContentStack` renderer boundary above all Paper rendering
- imperative transform preview so pointermove does not mutate React document state
- Select-mode foundation for topmost content hit testing and drag commit
- P1.1 QA diagnostics and content fixture controls
- `npm run qa:p1:contracts`, `npm run qa:p1`, and `npm run qa:current`

## Preserved

- P0 Paper Layer model and Paper Commands
- single-gesture Paper Eraser layer lock
- Page Logical Coordinate System
- two-finger viewport gesture ownership
- session-only Undo/Redo history persistence policy
- local-first IndexedDB autosave
- exact published `paperVersionId` hydration

## Migration

Existing local P0 documents remain on the stable IndexedDB key `p0-local-page`. When read, a valid schema V1 document is migrated in memory to PageDocument V2 and then autosaved back as V2.

No manual local-data reset is required.

## Product boundary

The P1.1 placeholder element is development/QA infrastructure only. Real content begins with P1.2 Ink.

## Validation

Local environment completed:

- editor-core + paper-engine + document-model + storage strict TypeScript
- ContentStack structural TypeScript
- EditorShell + QA structural TypeScript
- runtime assertions for migration / content z-order / transform Undo-Redo / lifted Paper commands / V2 round-trip

Full workspace dependency install/build remains delegated to GitHub Actions because the generation environment cannot reliably complete public npm installation.
