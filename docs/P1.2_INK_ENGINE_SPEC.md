# P1.2 — Ink Engine Specification

## 1. Goal

P1.2 introduces the first real Content Stack element: vector ink for handwriting and free drawing.

The Ink Engine must preserve all P0/P1.1 architectural rules:

- Page Logical Coordinates are canonical
- Konva is a renderer, not the data model
- pointermove never writes the persisted PageDocument
- one completed drawing/erase gesture produces one History operation
- two-finger viewport gestures cancel uncommitted one-finger editing
- local-first IndexedDB persistence remains the source of recovery

## 2. User-facing modes

Handwriting and Drawing are separate editor modes but use the same vector engine.

```text
handwriting
 drawing
 ink-erase
```

Baseline controls:

- Pen / Marker
- color
- width
- opacity
- ink eraser size

Advanced pressure curves, calligraphy simulation, brush marketplaces, handwriting recognition, and stylus-only features remain out of scope.

## 3. Canonical InkElement

One completed drawing gesture creates one `InkElement`.

```ts
interface InkElement extends ContentElementBase<'ink'> {
  mode: 'handwriting' | 'drawing';
  paths: InkPath[];
  style: {
    color: string;
    size: number;
    opacity: number;
    tool: 'pen' | 'marker';
  };
}
```

`paths[]` is intentionally plural. A fresh stroke starts with one path; partial erasing may split the original vector stroke into multiple retained paths while preserving the same element id and z-order.

No Canvas bitmap, Konva JSON, or DOM object is persisted.

## 4. Stroke coordinate model

The first page point becomes the InkElement transform origin. Stored path points are local to that origin.

This keeps ink compatible with the P1.1 generic Content transform model and allows Select mode to move/scale/rotate committed ink without rewriting every point.

Raw input is densified to a bounded logical spacing before commit. This improves partial eraser precision without requiring raster persistence.

## 5. Active drawing preview

```text
pointerdown
→ renderer-only InkStrokePreview begins

pointermove
→ mutable point buffer
→ Konva Line preview

pointerup
→ create InkElement
→ Add Content command
→ PageDocument
→ autosave
```

No React PageDocument mutation occurs on pointermove.

If a second finger joins before pointerup:

```text
cancel preview
→ do not create InkElement
→ do not add History entry
→ viewport pinch/pan owns the gesture
```

## 6. Ink Eraser semantics

Ink Eraser is independent from Paper Eraser.

Paper Eraser:

- one gesture locks to one PaperLayer
- never crosses into the layer below

Ink Eraser:

- may affect multiple existing InkElements in one gesture
- removes only intersecting ink portions
- never modifies PaperLayer, Image, Text, or placeholder data
- one completed eraser gesture = one History operation

Partial erasing is vector-based. Existing dense points that intersect the eraser path are removed and retained points are split into disjoint `InkPath`s.

## 7. Eraser preview performance

The active eraser is incremental.

Each new eraser segment applies only to the previous preview result rather than recomputing the full accumulated eraser polyline against the original document on every pointermove.

```text
committed ink
↓
preview state A
↓ + next eraser segment
preview state B
↓ + next eraser segment
preview state C
```

Cancel restores the committed ContentStack. Pointerup commits the final preview through one reversible command.

## 8. Rendering

Committed InkElements render inside `ContentStack` above the Paper Compositor.

Each InkElement uses a Konva Shape capable of drawing multiple vector paths. Renderer-only eraser preview replaces the Shape's temporary path attribute without changing the PageDocument.

The active drawing stroke and eraser cursor render above committed ContentStack pixels.

## 9. Selection compatibility

P1.1 Select mode can hit-test committed InkElements using renderer-independent polyline distance tests.

Selection is still session UI state and is not persisted.

Formal transform handles are deferred to later Product Shell work; P1.2 only guarantees compatibility with the shared transform foundation.

## 10. Persistence and migration

`PageDocumentV2` remains schema version 2. P1.2 expands the valid `ContentElement` discriminated union to include `type: 'ink'`.

Existing P0/P1.1 documents continue to decode unchanged.

Ink style, paths, transform, ids, timestamps, and ordering persist through the existing IndexedDB autosave boundary.

## 11. P1.2 non-goals

- pressure-sensitive calligraphy engine
- Apple Pencil / stylus-specific UX
- vector smoothing editor
- lasso selection
- multi-select
- brush asset marketplace
- handwriting recognition
- image/text implementation
- cloud sync / R2
