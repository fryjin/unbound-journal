# P0.4 Release Notes

## Delivered

- Real Paper Brush interaction on the 1000 × 1400 logical page
- Selecting a paper no longer fills/replaces the page
- New PaperLayer is created only after the first completed stroke
- Same-paper strokes append to the current top layer
- Switching papers creates a new top layer on the next stroke
- Vector `PaperMaskStroke` remains the product source of truth
- Isolated per-layer raster cache from Texture + Mask
- Mutable active-stroke renderer preview; no document state write on pointer/touch move
- Single-finger paint input mapped through P0.2 screen → page transform
- Multi-touch cancels an active stroke and suppresses painting until all fingers lift
- Desktop mouse painting for QA
- Adjustable P0 brush size: 60–360 logical units
- Development clear-page control and layer count
- Tier-1 + Tier-2 localized Paper Brush UI

## Validation target

In a normal npm environment run:

```bash
npm install
npm run typecheck
npm run build
npm run papers:validate
```

Manual mobile QA:

1. Selecting paper does not change the page.
2. First single-finger stroke reveals the selected paper only under the brush.
3. Grid/pattern coordinates remain continuous across separate strokes.
4. Additional strokes using the same top paper do not create new layers.
5. Select another paper; no layer appears until painting starts.
6. Paint the new paper; layer count increases by one.
7. Start painting, add a second finger, then pinch: the unfinished stroke is cancelled.
8. After pinch, keeping one finger down does not restart painting; lift all fingers first.
9. Zoom/pan and then paint: the mark lands at the correct logical page position.
10. At least five paper layers can be created without obvious interaction failure.
