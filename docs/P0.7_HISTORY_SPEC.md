# P0.7 — History / Undo / Redo Spec

## Goal

Make every committed Paper Engine edit reversible without persisting Canvas/Konva snapshots or turning high-frequency pointer movement into history entries.

## Core rule

History stores reversible commands over renderer-independent `PaperLayer[]` document state.

The renderer remains derived state:

```text
PaperLayer[]
+ PaperRuntimeAsset cache
→ PaperRenderLayer[]
→ Konva / Canvas
```

`PaperRuntimeAsset`, `HTMLImageElement`, Canvas caches and Konva nodes are never stored in Command History.

## History engine

`editor-core/history.ts` provides a generic command stack:

- `createCommandHistory()`
- `executeCommand()`
- `undoCommand()`
- `redoCommand()`
- `canUndo()` / `canRedo()`

Default history depth is 100 committed operations.

Executing a new command after Undo clears the Redo branch.

## Paper commands

`paper-engine/commands.ts` provides renderer-independent Paper commands.

### Append mask stroke

Used for:

- Paint on an existing PaperLayer
- Erase on an existing PaperLayer
- Fill on an existing matching PaperLayer

Undo removes exactly the committed stroke by stable stroke ID.

### Add PaperLayer

Used for:

- First Brush stroke after selecting another paper
- Fill with a selected paper different from the current top layer

Undo removes the exact layer by stable layer ID. Redo restores the same PaperLayer with the same mask data and material.

### Replace PaperLayer

Stores the exact pre-replacement and post-replacement PaperLayer models.

Undo restores:

- original `paperVersionId`
- original texture transform
- unchanged layer ID / createdAt
- exact prior `maskStrokes[]`

Redo reapplies the replacement.

### Clear PaperLayers

`Clear` remains a development QA control in P0, but it is now reversible. Undo restores the exact PaperLayer snapshot that existed immediately before Clear.

## Gesture boundary

High-frequency input stays outside History.

```text
pointer/touch move
→ mutable renderer preview
→ no history entry

pointer/touch end
→ one committed Paper operation
→ one Command History entry
```

A Brush gesture is one Undo step. An Eraser gesture is one Undo step regardless of how many move samples were captured.

## Undo / Redo interaction

Before Undo or Redo:

1. cancel active uncommitted Brush preview
2. cancel active uncommitted Erase preview and restore its committed raster
3. apply the History transition
4. let the renderer rebuild from the resulting `PaperLayer[]`

This prevents temporary renderer state from leaking into document history.

## Runtime asset cache

History contains only `paperVersionId` references. EditorShell keeps loaded `PaperRuntimeAsset` objects in a runtime cache keyed by `paperVersionId`.

This allows Replace → Undo → Redo without storing image/runtime objects in commands.

P0.9 persistence will reload runtime assets from the pinned version IDs rather than persisting this runtime cache.

## Shortcuts

Desktop QA shortcuts:

- macOS / Windows: `Cmd/Ctrl + Z` → Undo
- `Cmd/Ctrl + Shift + Z` → Redo
- Windows: `Ctrl + Y` → Redo

Text-editable targets are excluded so the future Text tool can own its native text undo semantics while editing.

## P0.7 acceptance checks

1. First Paint creating a PaperLayer undoes by removing the entire new layer.
2. Painting again on the same top paper undoes only the latest Paint stroke.
3. One Erase gesture undoes as one operation and restores the exact erased paper.
4. Fill on an existing layer undoes only the Fill mask stroke.
5. Fill that creates a new layer undoes by removing that new layer.
6. Replace → Undo restores the original material and exact mask shape.
7. Replace → Undo → Redo restores the replacement material again.
8. Undo several steps, then make a new edit; Redo becomes unavailable.
9. Clear → Undo restores all previous PaperLayers in the same order.
10. Undo / Redo never store Canvas, image or Konva snapshots.
11. Starting Undo/Redo during an uncommitted gesture cancels that gesture first.
12. History buttons correctly disable at the ends of the stack.
