# P0.8 — Persistence / Autosave Spec

## Goal

Persist the renderer-independent P0 paper document locally so committed work survives reloads and common browser interruptions without introducing cloud infrastructure.

## Persistence boundary

P0.8 persists only durable document state:

- document `schemaVersion`
- document id
- logical page size
- `PaperLayer[]`
- each layer's pinned `paperVersionId`
- texture transform
- vector paint / erase mask history
- created / updated timestamps

P0.8 intentionally does **not** persist:

- Konva JSON
- raster canvases or image objects
- runtime `PaperRuntimeAsset` cache
- viewport zoom / pan
- active brush / eraser previews
- selected tool or selected paper
- Undo / Redo stacks

After reload, the restored document becomes the new History baseline.

## Document schema

`paper-engine` owns `PaperPageDocumentV1` and the decode boundary.

```ts
interface PaperPageDocumentV1 {
  schemaVersion: 1
  id: string
  size: { width: 1000; height: 1400 }
  paperLayers: PaperLayer[]
  createdAt: string
  updatedAt: string
}
```

The decoder validates the complete layer / stroke structure and rejects unsupported schema versions rather than guessing or silently coercing data.

There is no legacy document migration yet because v1 is the first persisted schema. `decodePaperPageDocument()` is the explicit migration/validation entry point for future versions.

## IndexedDB

`packages/storage` provides a generic native IndexedDB adapter with no third-party dependency.

P0 values:

- database: `unbound-journal`
- database version: `1`
- object store: `documents`
- local document key: `p0-local-page`

The adapter exposes load / save / remove and keeps IndexedDB lifecycle concerns outside EditorShell.

## Autosave

Autosave is scheduled only after a committed document transition:

- Paint commit
- Erase commit
- Fill
- Replace
- Clear
- Undo
- Redo

Pointer / touch move does not schedule writes.

P0 debounce: **450 ms**.

Writes are serialized so an older slow IndexedDB write cannot complete after a newer write and overwrite the latest document.

`pagehide` and hidden-page transitions perform a best-effort flush of any pending value. Hard browser/process termination can never be guaranteed, so the durable boundary remains the latest completed IndexedDB transaction.

## Restore flow

1. Editor starts in persistence-loading state.
2. Read `p0-local-page` from IndexedDB.
3. If no document exists, start with an empty page.
4. If a valid v1 document exists, create a fresh Command History using restored `PaperLayer[]` as `present`.
5. Use each restored `paperVersionId` to resolve the matching Paper Pack manifest.
6. Reload runtime texture assets into the renderer cache.
7. Enable editing.

Editing is blocked only during the initial local restore read to prevent an empty initial state from racing and overwriting an existing draft.

## Failure behavior

- IndexedDB unavailable: editor remains usable, local autosave is marked unavailable.
- IndexedDB read/write error: editor remains usable and status reports local save failure.
- Invalid / unsupported stored document: editor ignores it, reports recovery failure, and does not crash.
- Missing runtime paper asset: document data remains intact; renderer hydration skips that asset until it becomes resolvable again.

## Cloud boundary

P0.8 is local-only. Do not introduce Cloudflare Workers, D1, R2, account identity, or cloud conflict resolution.

Cloudflare becomes relevant only when remote/public QA, cloud sync, remote asset delivery, or account-backed storage is required.
