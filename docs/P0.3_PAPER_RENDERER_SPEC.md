# P0.3 — Paper Renderer Spec

## Goal

Convert the P0.1 Paper Runtime Contract into actual page pixels inside the P0.2 logical viewport, without introducing Paper Brush or mask editing yet.

## Runtime flow

```text
/papers/index.json
↓
PaperCatalogEntry.manifest
↓
loadPaperRuntimeAsset()
↓
PaperRuntimeManifest + resolved runtime variant URLs
↓
PaperStack
↓
PaperTexture
↓
Konva page content group
```

## Renderer modes

### Pattern / tile

- Uses the `editor` runtime variant.
- Repeats one stable texture across the whole logical page.
- Texture coordinates remain in logical page space rather than brush-stamp space.
- `texture.defaultScale`, `rotation`, `offsetX`, and `offsetY` are consumed by the renderer contract.

### Full-sheet / cover

- Uses the `editor` runtime variant.
- Preserves source aspect ratio.
- Uses cover sizing against the logical page.
- Centers the source before applying manifest texture transform.
- PageViewport clipping prevents content from rendering outside the journal page.

## Paper stack

`PaperStack` draws an ordered array bottom → top.

P0.3 intentionally renders complete paper surfaces. P0.4 will add per-layer masks around these same surfaces. The texture renderer must not be rewritten when masks arrive.

## Development preview

P0.3 adds a temporary renderer-preview selector that exposes all 40 development papers. It exists only to verify:

- every manifest resolves;
- every editor texture loads;
- Pattern and Full-sheet use the correct rendering strategy;
- localized paper names remain usable.

Selecting a paper in this preview is **not** the final product interaction for applying paper. P0.4 replaces this development behavior with the actual paper-material / brush workflow.

## Boundaries

Not included in P0.3:

- brush masks;
- paint strokes;
- erasing;
- fill-page command;
- replace-paper command;
- undo/redo;
- persistence.
