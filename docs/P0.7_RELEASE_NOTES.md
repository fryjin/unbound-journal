# P0.7 Release Notes

## Delivered

- Generic renderer-independent `EditorCommand<State>` history engine in `editor-core`
- Default 100-operation Undo stack
- Redo stack with standard branch invalidation after new edits
- Paper-specific reversible commands in `paper-engine`
- Paint / Erase / Fill / AddLayer / Replace integrated into Command History
- Development Clear action made reversible
- Editor document state refactored from renderer-layer objects to pure `PaperLayer[]`
- Runtime Paper assets cached separately by immutable `paperVersionId`
- Undo / Redo buttons in the viewport HUD
- `Cmd/Ctrl+Z`, `Cmd/Ctrl+Shift+Z`, and Windows `Ctrl+Y` desktop QA shortcuts
- Active Brush / Eraser preview cancellation before Undo / Redo
- English / Japanese / Korean / Traditional Chinese History UI
- P0.7 specification and project status update

## Validation completed in generation environment

- P0.6 GitHub `main` baseline verified before implementation
- Starter Paper Pack validator: 40 papers valid (24 Pattern / 16 Full-sheet)
- `editor-core + paper-engine` strict TypeScript check: pass
- History runtime assertions: pass
  - AddLayer → Erase → Replace
  - multi-step Undo
  - multi-step Redo
  - new edit after Undo clears Redo
  - Clear → Undo restores prior state
- EditorShell strict type-structure check with local React/renderer type stubs: pass
- Tier-1 + Tier-2 locale keys present

## Environment limitation

The generation environment still cannot perform the full workspace dependency installation/build through its configured npm registry.

Before deployment, run in a normal npm environment:

```bash
npm install
npm run typecheck
npm run build
npm run papers:validate
```

## Cloudflare deployment

Cloudflare deployment is intentionally not started in P0.7. The project is still validating the local Paper Engine and does not yet require Workers / D1 / R2.

Deployment should be introduced only when a later milestone needs remote hosting, cloud sync, or cross-device/public QA. The user should be explicitly notified before that step.

## Manual QA required

1. Lay the first paper stroke, Undo, confirm the page returns to Base Paper; Redo restores the layer.
2. Add two more strokes on the same paper and Undo one at a time.
3. Erase part of the paper and Undo; confirm the exact erased region returns.
4. Fill, Undo, Redo.
5. Replace top paper, Undo back to the original material, Redo the replacement.
6. Create 2–3 different paper layers and confirm Undo/Redo preserves layer order.
7. Undo twice, perform a new Brush action, confirm Redo is disabled.
8. Clear the page, Undo, confirm all layers return.
9. Trigger Undo while a Brush or Eraser gesture is active; confirm the uncommitted gesture is cancelled first.
10. Test HUD buttons and keyboard shortcuts on desktop; test HUD buttons on narrow mobile widths.
