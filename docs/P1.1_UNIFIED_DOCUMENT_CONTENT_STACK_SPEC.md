# P1.1 — Unified PageDocument + Content Stack Foundation

## Status

Implementation ready for GitHub upload / CI / deployed QA.

## 1. Goal

P1.1 creates the shared document, history, renderer, selection and persistence boundary that all later P1 content types use.

No production Ink/Image/Text feature is introduced in this milestone. A query-gated development placeholder element is used only to prove the common Content Stack.

## 2. Dependency direction

```text
editor-core
  ├─ viewport / history
  └─ generic ContentElement + transform / hit-test geometry

paper-engine
  └─ PaperLayer / paper commands / legacy P0 decoder

        editor-core + paper-engine
                 ↓
          document-model
  ├─ PageDocument V2
  ├─ P0 V1 migration
  ├─ Paper command lifting
  └─ generic content commands

                 ↓
 editor-renderer-konva / web app
```

`paper-engine` does not depend on `document-model`, so the paper package remains reusable and no dependency cycle is introduced.

## 3. PageDocument V2

Canonical P1 page document:

```ts
interface PageDocumentV2 {
  schemaVersion: 2;
  id: string;
  size: Size;
  paperLayers: PaperLayer[];
  elements: ContentElement[];
  createdAt: string;
  updatedAt: string;
}
```

The current supported page size remains the P0 logical size `1000 × 1400` because the viewport renderer is still fixed to that logical page.

## 4. P0 persistence migration

The existing IndexedDB key remains `p0-local-page` for backward compatibility.

Startup decoder behavior:

```text
schemaVersion 1 (PaperPageDocumentV1)
→ validate with the existing strict P0 decoder
→ create PageDocument V2
→ preserve id / size / paperLayers / createdAt / updatedAt
→ elements = []
→ restore editor
→ schedule V2 autosave to the same storage key
```

Unknown future schema versions remain rejected rather than silently coerced.

The migration does not fabricate content and does not require clearing local data.

## 5. Unified History

P0 history stored `PaperLayer[]` as its present state.

P1.1 history stores the entire `PageDocument`:

```ts
CommandHistory<PageDocument>
```

Existing paper commands remain pure `PaperLayer[]` commands and are adapted through:

```ts
liftPaperCommand(command)
```

The lifted command modifies only `document.paperLayers` and preserves `document.elements`.

This avoids rewriting the accepted Paper Engine while giving Paper and Content one Undo/Redo timeline.

## 6. ContentElement foundation

P1.1 defines:

```ts
interface ElementTransform {
  x: number;
  y: number;
  rotation: number;
  scaleX: number;
  scaleY: number;
}
```

All values use Page Logical Coordinates.

The milestone includes a development-only:

```ts
DevelopmentPlaceholderElement
```

It exists only to validate the common stack before real Ink/Image/Text elements are added.

## 7. Content z-order

`PageDocument.elements[]` is bottom → top.

- renderer draws in array order
- hit testing searches reverse array order
- reorder Commands mutate array order
- there is no duplicate persisted `zIndex`

## 8. Selection and hit testing

Selection is editor/session UI state and is not persisted in `PageDocument`.

P1.1 rules:

- explicit Select interaction mode exists in the QA harness
- tap/click topmost content → select
- tap/click empty page → clear selection
- Paper Layers are never selected by Content Stack hit testing
- one selected element maximum
- rotated/scaled placeholder hit testing is resolved in renderer-independent geometry

## 9. High-frequency content drag

Content drag follows the same rule already validated by Paper Brush:

```text
pointermove
→ calculate transient ElementTransform
→ ContentStack imperative renderer preview
→ NO PageDocument setState
```

Gesture completion:

```text
pointerup
→ one TransformElement Command
→ PageDocument
→ debounced autosave
```

If a two-finger viewport gesture begins during drag, `onPageInputCancel` restores the committed transform and discards the transient preview.

## 10. Generic content commands

P1.1 provides:

- AddElement
- RemoveElement
- TransformElement
- ReorderElement

All are renderer-independent reversible `EditorCommand<PageDocument>` implementations.

## 11. Content renderer boundary

`ContentStack` is rendered after the complete Paper Compositor:

```text
PaperStack
PaperBrushPreview
ContentStack
```

Therefore paper never visually covers ContentElements, including while a paper stroke is still only a renderer preview.

P1.1 placeholder nodes are non-listening Konva nodes. Pointer ownership remains centralized in `PageViewport` / gesture routing rather than being captured by individual Konva elements.

## 12. QA harness

`/?qa=1` is extended for P1.1.

Automatic checks now include:

- PageDocument V2 JSON round-trip
- P0 V1 → P1 V2 migration
- paper runtime hydration
- persistence state
- IndexedDB round-trip
- viewport / DPR

QA-only controls include:

- add five real paper layers
- add placeholder content
- switch Paper / Select mode
- rotate selected placeholder
- scale selected placeholder
- send selected to back
- bring selected to front
- remove selected

The placeholder is not part of the product UI and should be removed/replaced as real ContentElement types arrive.

## 13. Acceptance gate

P1.1 closes only when:

- GitHub Actions `Current validation` is green
- existing P0 document restores without data loss and migrates to V2
- paper editing still passes regression checks
- placeholder add/select/drag/rotate/scale/reorder/remove all work
- content mutations Undo/Redo correctly
- reload restores placeholder elements
- two-finger gesture cancels uncommitted content drag
- Desktop Chrome and at least one physical mobile browser pass the P1.1 QA harness
