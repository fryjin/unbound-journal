# P0.6 — Fill / Replace Spec

## Goal

Complete the first Paper Engine creation loop by adding full-page paper fill and texture replacement without changing the established Texture + Mask document model.

## Fill Page

### Product rule

- Choosing a paper still does not create a layer.
- `Fill` is an explicit editing action.
- If the top PaperLayer already uses the selected `paperVersionId`, Fill appends a full-page paint mask to that layer.
- If the selected paper differs from the top PaperLayer, Fill creates a new top PaperLayer and initializes it with a full-page paint mask.
- Fill never mutates lower PaperLayers.

### Data representation

P0.6 intentionally keeps `PaperMaskStroke` as the only committed mask primitive.

`createFillPageStroke()` generates one round `paint` stroke centered on the logical page. Its radius exceeds the page half-diagonal, so the stroke covers every page corner. The page compositor clips the result to the page rectangle.

This gives Fill the same properties as normal brush painting:

- renderer-independent document data
- deterministic mask replay
- compatible top-visible hit testing
- a single future Undo/Redo command can remove the fill operation
- no special renderer-only `isFilled` flag

## Replace Paper

### Product rule

Replace changes the material of one existing PaperLayer while preserving the shape already created by the user.

P0.6 UI targets the current top PaperLayer because a full layer manager is intentionally out of scope. The data helper accepts any PaperLayer, so a future layer selector can choose another target without changing Replace semantics.

### Preserved fields

Replace preserves:

- `PaperLayer.id`
- `PaperLayer.createdAt`
- layer order
- complete `maskStrokes[]` history, including both paint and erase strokes

Replace changes:

- `paperVersionId`
- `texture` to the replacement paper asset's default texture transform
- renderer `asset`

The replacement does not create a new PaperLayer.

## Interaction boundary

Fill and Replace are available in `Lay` mode only.

- Eraser mode disables both actions.
- Any active uncommitted brush/erase preview is cancelled before Fill or Replace runs.
- Replace is disabled when the selected paper is already the material used by the top PaperLayer.

## Command History readiness

P0.6 does not implement history yet, but the operations are deliberately command-friendly:

- Fill = append one known `PaperMaskStroke`, or create one known PaperLayer
- Replace = swap one PaperLayer material while retaining stable layer identity and mask history

The future History milestone can capture before/after state without changing P0.6 data contracts.

## P0.6 acceptance checks

1. Selecting a paper without painting/filling still creates no PaperLayer.
2. Fill on an empty page creates exactly one full-page PaperLayer.
3. Every logical page corner is visible after Fill.
4. Fill with the same selected top paper reuses the same PaperLayer.
5. Fill with another selected paper creates a new top PaperLayer.
6. Erasing the filled top layer reveals lower paper normally.
7. Replace keeps the target layer `id`, `createdAt`, mask stroke count and mask geometry unchanged.
8. Replace updates the visible texture without changing the mask shape.
9. Replace does not change layer order or layer count.
10. Fill / Replace are unavailable while Erase mode is active.
11. Tier-1 and Tier-2 locales fit the mobile Paper controls.
