# P0.3 Release Notes

## Delivered

- `PaperRuntimeAsset` resolves manifest-relative runtime URLs.
- Pattern papers render with repeated page-space textures.
- Full-sheet papers render with aspect-preserving cover behavior.
- `PaperTexture` isolates runtime texture loading and rendering strategy.
- `PaperStack` establishes ordered bottom → top paper rendering.
- PageViewport's existing logical-page clip contains all paper pixels.
- Runtime image loading reports loading / ready / error state.
- Development renderer preview can switch across all 40 Starter Paper Pack assets.
- Preview uses localized paper titles for en / ja-JP / ko-KR / zh-Hant.
- P0.3 does not define paper-application UX; preview selection is a QA control only.

## Validation completed in generation environment

- `npm run papers:validate` → 40 papers valid.
- Renderer editor-asset dimensions checked:
  - 24 Pattern assets are square.
  - 16 Full-sheet assets match the current 5:7 logical page ratio.
- Manifest-relative runtime URL resolution was reviewed against the current fixture layout.
- TypeScript / TSX source syntax checks completed for changed files.

## Environment limitation

The generation environment still cannot complete the normal workspace install because its configured npm registry cannot resolve all public dependencies. Before deployment, run in a normal npm environment:

```bash
npm install
npm run typecheck
npm run build
npm run papers:validate
```

## Manual QA

Use the P0.3 renderer preview to check:

1. Switch through Pattern papers and confirm repetition is continuous across the page.
2. Switch through Full-sheet papers and confirm the image covers the page without distortion.
3. Zoom to 4× and inspect texture sharpness / seams.
4. Pan to every page edge and confirm no paper pixels escape the page clip.
5. Change locale and confirm the selector labels update.
6. Rapidly switch several papers and confirm stale image loads do not replace the latest selection.
7. Test on iPhone Safari, Android Chrome, and Desktop Chrome.
