# P0.4 — Paper Brush Spec

## Goal

Turn paper selection into real journal creation: a user chooses a paper and paints its visible region onto the logical page with one finger.

## Frozen behavior

1. Selecting a paper does **not** create a PaperLayer.
2. The first completed paint stroke creates a PaperLayer if the selected paper differs from the current top layer.
3. Additional strokes with the same selected paper append to the current top layer.
4. Switching to a different paper does not modify the document until the next completed stroke.
5. Paper texture coordinates are page-fixed; the brush changes only the mask.
6. Two-finger gestures cancel the active single-finger preview and never commit a paper stroke.
7. High-frequency movement updates only a mutable renderer preview. React document state changes only when a stroke is committed.

## Logical model

```text
PaperLayer
├── paperVersionId
├── texture transform
└── maskStrokes[]
    └── operation: paint | erase
```

P0.4 creates `paint` strokes only. `erase` remains in the contract for P0.5.

## Rendering strategy

Committed layers use isolated 1000 × 1400 raster caches generated from:

```text
Runtime Texture + Vector MaskStroke[] → Raster PaperLayer Cache
```

The mask is rasterized separately from the texture and combined with `destination-in`. This keeps the product document vector-based while preparing layer isolation for the eraser milestone.

The active stroke uses a mutable preview canvas and does not update React state on every move.

## Brush

- Round
- Hard edge with canvas antialiasing
- 100% coverage
- Default logical size: 180
- Adjustable range: 60–360 logical units

## Input routing

Single touch:

```text
screen point → PageViewport transform → logical page point → Brush Preview
```

Two touches:

```text
cancel active brush preview → viewport pinch/pan
```

After a multi-touch gesture begins, a remaining single finger cannot resume painting until all fingers are lifted. This prevents accidental marks after pinch/zoom.
